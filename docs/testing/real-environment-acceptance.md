# 真实环境验收清单

这些项目只能在真实账号、真实服务或 Windows 机器上验证，源码测试和打包 smoke 不能替代。
每项完成后，把「需要回传的证据」发给维护者，由维护者记录到对应计划文档。不要回传密码、
授权码、Cookie、API key 或完整的邮件邀请链接（链接里含一次性 token）。

状态：2026-10-01 编写，对应 Desktop `0.1.0-alpha.42`、New Money Server `9185341`。

## 1. 应用内升级到 alpha.42

前提：一台 Windows x64 和一台 Apple Silicon Mac，各自安装 alpha.41 或 alpha.40。

1. 打开 app，进入设置里的更新入口，点「检查更新」，应显示有新版本 `0.1.0-alpha.42`。
2. 点「下载并安装」。Windows 会出现原生安装进度窗口并自动关闭；Mac 会自动退出并重新打开。
3. 重启后在设置里确认版本是 `0.1.0-alpha.42`、名称是 New Money。
4. 确认原来的会话、Provider 配置仍在，能正常发送一条消息。

需要回传的证据：每个平台升级前后的版本截图；是否出现任何错误提示。

## 2. alpha.42 新增的确认框

1. 在一个已信任的工作区里放一个可执行文件（Mac 用 `.command` 或 `.sh`，Windows 用 `.bat`）。
2. 在文件树里右键它，选「使用系统默认应用打开」。应先弹出原生确认框：
   「“文件名”是可执行文件，用系统默认应用打开会直接运行它。」默认按钮是「取消」。
3. 点「取消」，文件不应运行；再试一次点「运行」，文件才运行。
4. 对普通文档（如 `.md`、`.pdf`）做同样操作，应直接打开，不弹确认框。
5. 进入「设置 → 下载源与网络」，把 npm 源改为「自定义」并填一个地址后保存，应弹出原生确认框，
   列出这个地址。点「取消」后，设置应保持原样。

需要回传的证据：两个确认框的截图；取消后文件没有运行、设置没有改变。

## 3. 账号显示名称在重启后保持

1. 在 New Money 网页后台（`https://newmoney.52671314.xyz/account`）把个人显示名称改成一个新值。
2. 在 Desktop 打开「设置 → 账户与数据」，点「刷新状态」，应显示新名称。
3. 完全退出 Desktop（Mac 用 Cmd+Q；Windows 从托盘或任务管理器确认进程已退出），再重新打开。
4. 不点刷新，直接查看「设置 → 账户与数据」，应仍显示新名称。

需要回传的证据：刷新后和重启后的截图（可以打码邮箱）。

## 4. 设备授权与项目绑定的完整流程

前提：账号属于至少一个团队，团队里至少有一个项目。

1. 在 Desktop「设置 → 账户与数据」点「登录 New Money」，再点「打开登录授权页」。
2. 在打开的浏览器页面里确认授权，回到 Desktop，应显示已登录的账号。
3. 进入「设置 → 上下文与记忆」，在「当前团队」里选择团队，在「当前项目绑定」里为当前工作区选择项目，
   保存。
4. 新建一个会话，用「选择团队与项目」选中这个团队和项目，让 Agent 搜索或读取一条团队共享知识，
   应能返回结果。
5. 退出登录，确认本地私人会话和记忆仍在；再次登录后，项目绑定仍然存在。

需要回传的证据：已登录状态、项目绑定、成功读取团队知识的截图；退出再登录后绑定是否保留。

## 5. 真实成员接受邀请

**先决条件，需要负责人决定：** 生产环境当前关闭了注册（`registrationEnabled=false`）。
被邀请人必须已经有 New Money 账号；如果对方还没有账号，需要先临时开放注册，或由管理员另行创建账号。

1. 团队管理员在网页后台「成员」页邀请对方的邮箱。
2. 被邀请人打开邮件里的邀请链接，用同一个邮箱登录。
3. 页面应显示团队名称和角色；明确点击确认后加入团队。
4. 被邀请人在 Desktop 登录后，应能在「当前团队」里看到这个团队。
5. 管理员在「成员」页确认对方已加入；必要时演练一次移除成员，确认对方随后无法再读取团队知识。

需要回传的证据：成员列表截图；被邀请人在 Desktop 里看到团队的截图。不要转发邀请链接本身。

## 6. Windows 性能基线（需要开发环境）

前提：Windows x64 机器上有本仓库的 checkout、Node `24.18.0` 和 Corepack，并按
`CONTRIBUTING.md` 完成 `corepack pnpm install --frozen-lockfile`。

```powershell
corepack pnpm run performance:prepare
corepack pnpm run performance:electron
```

采样期间不要操作电脑或运行其他重负载程序。结果写入
`artifacts/performance/electron-win32-x64.json`。

需要回传的证据：这个 JSON 文件，以及机器的 CPU、内存和 Windows 版本。维护者会据此校准
`docs/testing/performance.md` 里按 macOS 设定的 1.2 s 初始化预算和 160 MiB 独占内存预算。
