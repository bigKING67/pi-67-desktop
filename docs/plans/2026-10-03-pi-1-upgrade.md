# Pi 1.0 SDK compatibility upgrade

Status: completed within authorized scope; native MCP migration, CLI cleanup and alpha.43 cross-platform candidate verification accepted
Owner: Codex
Started: 2026-10-03
Last updated: 2026-10-03

## Goal

Upgrade the pinned Pi suite from 0.86.1 to 1.0.0 while preserving existing
Desktop tool authorization, Pi JSONL ownership, extensions, memory integration,
model selection, cancellation and recovery behavior.

Follow-up goal: retire `pi-mcp-adapter` completely from Desktop execution and
distribution, with Pi native MCP as its only MCP connection/tool owner. The user
explicitly accepted a minimal exact-version pnpm patch for upstream host seams
and the verified initialization-shutdown defect.

## Non-goals

No Pi Durable migration, Codemode activation, automatic
model routing, provider changes, UI redesign or unrelated dependency upgrade.

## Acceptance criteria

- Exact Pi dependency pins and lockfile agree with the release runtime contract.
- Real SDK tests exercise built-in source identity and existing tool policy.
- Session/context/extension regressions, full source gate, production Renderer
  E2E and local native Electron checks pass, or failures retain explicit evidence.
- Standard macOS unsigned preview packages, smokes and opens the new artifact.
- Windows hosted candidate certification follows the subsequently authorized
  candidate boundary below. Target-user manual and paid-provider acceptance
  remain separate and unverified.

## Delivery boundary

- Local implementation, dependency install, offline/synthetic verification and
  standard macOS unsigned preview are authorized by the user's continuation.
- No commit, push, remote workflow dispatch, upload, signing or release.
- No paid model calls or destructive tests against the user's profile.
- User's follow-up continuation additionally authorizes the team-chat E2E wait
  correction, full Renderer rerun and native MCP gap assessment. Assessment does
  not authorize activating native MCP or changing the existing adapter route.
- The next continuation authorizes a test-only native MCP prototype with a
  synthetic stdio server and isolated profile. It may characterize identity,
  Desktop policy, raw-output persistence, cancellation and process cleanup.
  Product activation, user configuration migration and real MCP services remain
  outside this boundary.
- The latest user instruction supersedes the prototype-only native MCP boundary:
  local runtime/config/policy/bundle migration and an auditable Pi 1.0.0 pnpm patch
  are authorized, through applicable source/build/native/macOS-preview checks.
  User-owned files/data are preserved; no remote publication or user-profile
  destructive cleanup is implied. Native HTTP/OAuth unsupported behavior must be
  explicit; no new localhost listener may be introduced.

- First stabilize the existing product on fixed Pi 1.0.0; native MCP, Codemode,
  nested-tool UX and Durable adoption remain separate decisions.

  browser67 stays direct; ordinary/configured legacy proxy tools are deferred.
  Codemode remains outside scope. Configuration translation is runtime-only and
