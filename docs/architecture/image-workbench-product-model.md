# 图像工作台产品模型与实施规划

状态：`proposed — 产品模型、架构边界与分阶段验收已由用户于 2026-10-08 确认方向；尚无实现、测试或打包证据`

决策记录：`docs/adr/0010-image-workbench.md`。首个执行计划：`docs/plans/2026-10-08-image-workbench-p1.md`。

本文定义 New Money 图像工作台的产品模型、用户与任务、信息架构、工作台布局、核心流程、
Agent 协作合同、质量闸门、数据模型、进程与协议边界、性能与可访问性预算、非目标和分阶段
验收。它承接 `PRODUCT.md` 的 Harness principles 与 `DESIGN.md` 的 Window structure；被采纳的
行为、交互与 token 变化仍须在实现的同一改动中写入这两份权威文档，本文不替代它们。

## 1. 决策摘要

New Money 把 craft67 `creative-craft` 的图像执行器**移植**为自有的首方图像引擎，把
`creative-craft` 的创意方法论 Skill 继续作为固定快照引用，并在工作模式里提供一个由 Agent
驱动、与人共用同一引擎的图像工作台：普通用户用对话委派，专业设计师直接操作画布与面板，
两者的每一次修改都落在同一份可回退的分层工程上。

```text
creative-craft Skill（方法：brief → 路线 → 导演 → 制作 → 评估）   固定快照，不改
+ New Money image-engine（工程、修订、候选、合成、渲染、Provider） 移植后自有演进
+ image-pi-extension（把引擎注册为 Pi 工具，Agent 直接调用）
+ 图像工作台（侧栏入口、创作库、画布、图像 Inspector、对话同屏）
+ 代码强制的质量闸门（保护区像素、确定性文字、规格检查）
+ 任务级预算、用户自选模型、无标识
```

明确架构决策：

1. 引擎运行在 Agent Host utility process 内，渲染与合成在 `worker_threads` 池中执行；
   Agent 通过 Desktop 自有 Pi 扩展注册的工具调用它，人通过 Agent port 上的 protocol 命令
   调用它。**一个引擎、一个进程、一个队列**，没有双写者。
2. 图像工程目录是产物真源；Pi JSONL 仍是对话真源；Main 持有可丢弃的创作库索引。
   工程内容不进入 Workbench 持久化、日志、诊断或遥测。
3. 确定性操作（改字、改价、移动、缩放、重排、换比例、锁定、撤销、候选接受/丢弃）
   不经过模型，毫秒级落地；生成与判断类操作交给 Agent，并附结构化上下文。
4. 生图模型由用户在 Pi Provider 配置中自选；Desktop 不推荐、不路由、不另建凭据存储。
5. 不做任何 AI 生成标识（显式或元数据）。回执与嵌入参数只服务复现与撤销。
6. 不内嵌 Compositor 或任何 GPL 画布；不加本地 server、本地 WebSocket、第二 runtime。
7. renderer 继续不碰文件系统：预览与缩略图经 Main 的只读 `app://` 路由按内容哈希读取。

## 2. 愿景、定位与受众

**一句话**：把图像生产、编辑、处理、优化交给 Agent，人只做判断；设计师想亲手改时，同一张画布
随时可以直接操作。

**它为什么值得存在**：市面上的生图产品要么只有对话（ChatGPT Images、Gemini），改一处要重生成
整张；要么只有编辑器（Photoshop、Canva），Agent 只是外挂。New Money 的差异在于三点同时成立：

- **委派与操作共用一份工程**。Agent 改的和人改的都是同一组对象、同一条修订链，可以互相接着改。
- **结果由代码担保**。商品本体、Logo、文案不被模型改坏，是引擎检查过的事实，不是提示词里的希望。
- **本机、本地文件、本地上下文**。直接读用户的素材文件夹、工作区和 commerce-growth-os 的卖点，
  原图和凭据不离开电脑。

**受众**：

| 用户 | 典型任务 | 主要用什么 |
| --- | --- | --- |
| 委派者（运营、创业者、普通人） | 一张图出一套、换背景、改文案、出多尺寸 | 对话 + 候选条 + 画布只看不改 |
| 设计师 | 精确排版、多方向比稿、局部返工、导出规格 | 画布直接操作 + 图像 Inspector + 对话补创意 |
| Agent | 理解 brief、出候选、自检、定向修改、交付 | 引擎工具 + 结构化上下文 + 预算 |

委派者和设计师不是两种模式，而是同一界面的两种使用深度：Inspector 折叠时是委派台，展开时是编辑器。

## 3. 产品原则

1. **帮人委派，不是又多一件要管的事**。默认预算内 Agent 自己跑完，只有超预算、换贵模型或
   达到轮次上限时问一次；没有逐步确认，没有节点图，没有预设墙。
2. **原始像素不可破坏**。所有编辑都是对象级修订，模型输出只能以候选形式进入，接受时重新合成并
   校验；从不在模型输出上叠加下一轮模型输出。
3. **一切可回退、可比较**。修订链不可替换，候选不可变，历史面板可回到任一修订；对比是一等交互。
4. **真实结果，不是承诺**。`ready` 只表示「技术上可审阅」；VLM 的判断是观察记录，默认
   `UNVERIFIED`；接受候选是人的决定。
5. **确定性优先**。文字、价格、Logo、尺寸规格走排版层与检查器，不靠模型「尽量」做对。
6. **模型是用户的**。用什么模型、花多少钱由用户在 Pi 配置里决定；Desktop 只展示能力与费用。
7. **设计师看到的就是文件**。工程是普通目录，复制即备份，搬走即可重开；没有专有二进制。

## 4. 核心概念与产品词汇

| 词汇 | 含义 | 面向用户的名字 |
| --- | --- | --- |
| Project | 一个图像工程目录：画布、对象、素材、修订、候选、回执 | `图像项目` |
| Canvas | 画布尺寸、背景与颜色空间（sRGB） | `画布` |
| Object | image / text / rect 等对象，自底向上排列；可锁定、可隐藏 | `图层` |
| Revision | 一次不可替换的工程状态，带父摘要与变更说明 | `修订` |
| Batch | 一次编辑提交（人或 Agent）；或一次生成运行产出的一组候选 | `修改` / `一轮生成` |
| Candidate | 针对某个图层的不可变生成或合成结果，状态 ready / stale / accepted / discarded / decision_pending | `候选` |
| Protected region | 像素级保护蒙版；接受候选时逐字节校验不变 | `保护区` |
| Mark | 画布上的一个区域加一句指令，多个标记一次提交 | `标记` |
| Reference | 带角色的参考图：保留主体 / 保留风格 / 取构图 | `参考` |
| Task | 一次 Agent 执行实例（沿用 `PRODUCT.md` 的 `任务`） | `任务` |
| Export | 一次导出产物与回执，绑定修订与摘要 | `导出件` |
| Library | App 自有的图像项目根目录，注册为普通 Workspace | `创作库` |

`Session` 继续只用于 Pi JSONL、Protocol 与诊断语境；用户界面不把图像项目叫 Session。

## 5. 信息架构与导航

### 5.1 侧栏

工作模式下，导航栏自上而下为：品牌行 → `工作 | 聊天` → **`图像`** → `搜索对话` → 工作区文件夹树。

- `图像` 是去处：选中后中心区域切换为创作库；搜索框紧贴它过滤的文件夹树。
- 聊天模式隐藏 `图像`，与现有「聊天替换工作侧栏」规则一致；设置页优先级不变。
- 其它能力（视频等）只有在执行器真实可用时才加入，不放占位项。
- 创作库是一个真实 Workspace，但**不出现在文件夹树**里；它只从 `图像` 进入。

### 5.2 归属规则

| 发起位置 | 归属 | 导出默认位置 |
| --- | --- | --- |
| `图像` → 新建 | 创作库 | 创作库项目目录 `exports/` |
| 某工作区 `+` → `新建图像项目` | 该工作区（项目目录固定为工作区内的隐藏子目录 `.newmoney/images/<id>/`，随工作区所在磁盘） | 该工作区 |
| 普通对话里对图片附件选择 `在图像工作台中打开` | 该对话所属工作区 | 同上 |

工作区归属的项目目录不会被自动加入 Git；是否提交由用户在工作区里决定。导出到其它位置始终是
显式动作（`导出到…`），从不静默写入仓库。每个项目卡片和每个候选都能跳回生成它的那一轮对话。

### 5.3 创作库视图

- 网格卡片：缩略图（最新修订）、标题、画布尺寸、修订数、未决候选数、最近更新时间、归属
  （创作库 / 工作区名）。
- 排序：最近更新；筛选：归属、有未决候选、有运行中任务。`搜索对话` 的索引也覆盖图像项目标题
  与其对话，结果带 `图像` 类型标记。
- 空状态：一句说明加两个入口：`新建图像项目`、`从图片开始`（选择本地图片直接建项目）。
- 卡片动作：打开、重命名、在 Finder/Explorer 中显示、复制项目、归档；删除需确认且默认取消。

### 5.4 TitleBar

打开图像项目时 TitleBar 显示项目标题；Workspace 归属的项目显示 `工作区 / 项目标题`。
Repository 状态控件只在工作区归属的项目上保留原语义；创作库项目显示 `创作库`。
Inspector 切换钮位置不变。

## 6. 工作台布局

图像项目沿用三区壳，但中心区与 Inspector 内容替换：

```text
+----------------------------------------------------------------------------+
| 导航 | 项目标题（居中）       | 任务状态 | 通知 | ⌘ | Inspector 开关 |
+------+--------------------------------------------+----------------------+
| 图像 |  画布工具条：缩放 适配 选择 标记 对比 保护区  |  图层 属性 候选 历史 导出 |
| 搜索 |                                            |                      |
| 树   |              画  布                         |  （随当前标签与选中   |
|      |                                            |   对象变化）          |
|      +--------------------------------------------+                      |
|      |  底部坞：候选条  |  对话（可折叠、可拖高）     |                      |
+------+--------------------------------------------+----------------------+
```

- **画布区**：缩放 / 平移 / 适配；选中高亮与变换手柄；双击文字进入行内编辑；`标记` 模式画矩形并
  在旁边写一句指令；`对比` 模式在当前修订与候选间做拉杆或并排对比；`保护区` 叠加显示；透明用棋盘格；
  放大到 400% 以上显示像素网格。
- **底部坞**：左侧候选条按批次分组，每张候选有状态标记（ready / stale / accepted / discarded）、
  来源（模型 / 本地合成）与接受 / 丢弃 / 对比；右侧对话是普通 Pi 对话，Composer 自动附带结构化上下文。
  坞可折叠为一条状态栏，也可把对话拖到右侧与 Inspector 并列（宽屏）。
- **图像 Inspector** 五个一等标签，保持「五个等宽一行」的既有合同：
  - `图层`：自顶向下列表；拖拽重排；可见 / 锁定开关；多选；右键菜单（复制、删除、置顶、置底、
    转为保护区）。锁定变更按引擎规则单独成一批。
  - `属性`：随选中对象变化。共有：位置、尺寸、不透明度、锁定、可见。image：适配方式、替换素材。
    text：文本、字号、颜色、对齐、行高、字体（工程绑定字体列表）。rect：颜色、圆角。画布：尺寸、
    背景、预设比例（1:1、3:4、4:5、9:16、16:9、自定义）。数值可拖动标签微调。
  - `候选`：当前批次与历史批次；每张候选的回执摘要（模型、质量档、尺寸、耗时、费用估计、
    `visual_quality: UNVERIFIED`）；接受 / 丢弃 / 对比 / 复用参数。
  - `历史`：修订列表（序号、时间、来源 人 / Agent、说明、变更对象数）；点击预览，`回到此修订`
    生成新修订而非删除历史；候选接受在历史中可见。
  - `导出`：预设（原尺寸 PNG、平台预设、多尺寸同出）、导出位置、文件名模板；导出回执列表。
- **折叠态**：Inspector 关闭时，画布工具条仍保留对比与保护区开关；委派者只用画布 + 底部坞即可完成任务。
- **响应式**：≥1320px 三区；1040–1320px Inspector 变为覆盖式抽屉；<1040px 底部坞仅保留对话，
  候选条移入 Inspector `候选` 标签；<760px 沿用导航抽屉规则。

所有视觉按 `DESIGN.md` 的语义 token、圆角与动效规则实现；画布 chrome 使用安静表面与单像素分隔，
不引入新的调色板或第二套组件家族。做界面时按 `design-craft` 的 `craft` 模式加载对应参考并用
browser67 在打包预览上取证。

## 7. 核心流程

每个流程都定义正常、空、加载、错误与长数据四类状态；未列出的状态在实现时补入 `PRODUCT.md`。

### A. 从图片开始（委派者主路径）

1. `图像` → `从图片开始` 或把图片拖进创作库。
2. 引擎 `create-photo`：原图按原尺寸锁定为底层图层，自动生成保护区（整张照片），文本对象独立。
3. 画布显示；底部坞对话给出一句引导：「告诉我要做什么，比如换背景、加标题、出三个尺寸」。
4. 用户一句话 → Agent 读取结构化上下文 → 按预算生成候选 → 候选条出现。
5. 用户选一张接受 → 引擎重新合成并校验保护区 → 新修订。
6. 标题 / 价格由 Agent 添加为文本对象（排版层），或用户在画布直接改。
7. `导出` → 多尺寸同出 → 回执。

失败态：模型请求失败（可重试，不扣候选额度）；保护区校验失败（候选标 `candidate_failed`，
原因可见，不自动再次生图超出预算）；文本超框（行内编辑时即时提示并拒绝提交）。

### B. 直接编辑（设计师主路径）

- 选中 → 拖动 / 缩放 → 指针抬起时提交一个 `update_object` 批次，携带当前修订号。
- 行内改字 → 失焦或回车时先 `dry-run`（字宽与排版高度），通过才提交。
- 多个连续微调在 300ms 内合并为一批；撤销（⌘Z）是 `revert_to` 新修订，重做是再一次 `revert_to`。
- 冲突：提交时 `base_revision` 过期（Agent 刚写入）→ 画布刷新到最新修订，用户的改动以草稿形式保留并
  提示「Agent 刚更新了项目，再次提交以应用到新修订」；不静默重基。

### C. 候选评审

- 候选条按批次分组；单击在画布预览（不改修订）；`对比` 打开拉杆 / 并排；接受 / 丢弃各写一条不可变决定。
- 陈旧候选（基础修订已变）仍可查看和对比，但接受前必须以新 ID 重新暂存；界面直接提供 `基于当前修订重算`。
- 决定锁异常（进程中断）在候选面板显式呈现并提供经确认的释放动作，不自动猜测。

### D. 多处标记返工

- `标记` 模式：画 1–N 个矩形，每个旁边一句指令，一次提交。
- 提交内容进入 Composer 作为结构化上下文：区域（素材栅格坐标）、指令、涉及对象。
- Agent 为每个区域生成局部候选（蒙版合成：生成区 / 保护区 / 羽化区由引擎根据标记与保护区推导），
  用户逐个接受。

### E. 参考图

- 参考槽位固定三种角色：`保留主体`、`保留风格`、`取构图`；每槽最多 3 张（随 Provider 能力上限）。
- 槽位内容随消息发送给 Agent，并写入生成回执；不同 Provider 的参考语义差异由 Provider profile 声明。

### F. 导出

- 预设 + 自定义；多尺寸同出通过 `set_canvas` + 对象重排生成派生修订，不缩放成品图。
- 导出前检查：尺寸、文本超框、保护区完整；平台预设附带规格检查（尺寸、文件大小、背景）。
- 导出件与回执列入 `导出` 标签；导出目录在项目外时按用户选择，始终是新目录。

### G. 处理与优化（无画布的轻任务）

- 格式转换、缩放、压缩、裁切、sRGB 归一化、批量重命名：Agent 用引擎的处理工具直接对文件操作，
  产出导出件与回执，不要求建工程。
- 放大、去背景、重打光等依赖模型的处理走 Provider；能力由 profile 声明，不可用时界面明示。
- 入口：创作库 `处理图片…` 与对话里对附件的快捷动作。

### H. 从工作区发起与交接

- 工作区 `+` → `新建图像项目`；项目目录在工作区内；完成后可 `导出到工作区路径`。
- Team Chat 交接沿用 Work Card：发送标题、目标、验收标准与导出件链接或附件；不发送工程、提示词或对话。

## 8. 画布与编辑能力分级

| 级别 | 能力 | 阶段 |
| --- | --- | --- |
| L1 基础 | image / text / rect；位置、尺寸、不透明度、锁定、可见；适配方式；画布尺寸与背景；修订与撤销 | P2 |
| L2 专业 | 变换手柄与吸附（画布边、中心、对象边）；行内文字编辑；多选与对齐分布；图层拖拽；预设比例重排；工程绑定的用户字体 | P3 |
| L3 进阶 | 图层组；逐图层蒙版；混合模式；旋转与翻转（非破坏）；渐变与更多形状；基础调整（亮度、对比、饱和、模糊） | P4 |
| 非目标 | 像素画笔、仿制图章、钢笔矢量、RAW 显影、滤镜市场 | — |

每一级的新对象类型与字段都先在引擎 schema 中定义并带共享样例，再进入 protocol 和界面。

## 9. Agent 协作合同

### 9.1 工具（由 `image-pi-extension` 注册）

| 工具 | 作用 | 备注 |
| --- | --- | --- |
| `image_project_read` | 读取当前 / 指定修订、摘要、对象列表、候选状态 | 返回紧凑 JSON 与预览路径 |
| `image_project_edit` | 提交编辑批次，支持 `dry_run` | 引擎校验结构、字形、排版、锁定 |
| `image_render` | 渲染预览或导出 | 预览最长边 640px，供视觉模型查看 |
| `image_candidate_stage / list / compare / accept / discard` | 候选生命周期 | 决定不可变 |
| `image_generate` | 按 Image Job 调 Provider 生成或编辑，结果进入暂存区 | 受预算与轮次上限约束 |
| `image_photo_create` | 从照片建项目 | 自动保护区 |
| `image_copy_variants` | 一次改文案同步多个版式 | 派生工程 |
| `image_process` | 无工程的文件处理 | 转换、缩放、压缩、裁切 |

Agent 不再通过 Bash 调 CLI；工具结果包含可被视觉模型读取的预览文件路径。Pi ResourceLoader
仍是唯一扩展加载器，扩展按 Desktop-owned extension build boundary 编译与登记。

### 9.2 结构化上下文

从项目页发出的每条消息自动附带：项目 ID、当前修订号、选中对象 ID、标记列表、参考槽位、画布规格、
未决候选数。Composer 以折叠行展示附带内容（「已附带：2 个标记，1 个选中图层」），用户可移除。

### 9.3 自主与询问边界

| Agent 可自主 | 必须询问 |
| --- | --- |
| 预算内的生成、重试、对比、dry-run、渲染预览 | 超预算、切换更贵模型、超过轮次上限 |
| 添加 / 修改文本与形状对象、重排、换比例 | 修改或删除锁定对象、改变保护区 |
| 暂存候选、标记陈旧 | 接受或丢弃候选（除非用户在消息里明确授权「直接采用最好的」） |
| 回到基础修订重来 | 删除项目、导出到项目外、覆盖已有导出 |

Agent 的每轮工作在对话里以可展开的「修改卡」呈现：改了哪些对象、生成了几张候选、校验结果、费用估计。

### 9.4 预算与轮次

- 项目级预算默认值来自 `设置 › 图像`（例如草稿候选 4 张 low、定稿 1 张 high、每任务最多 3 轮）。
- 费用估计基于 Provider profile 的官方价格表，标注「估计」；真实账单 `UNVERIFIED`。
- 轮次上限到达或连续两轮校验失败 → Agent 停止、汇报、建议下一步；不静默继续。

## 10. 质量与安全闸门（引擎代码强制）

1. **保护区像素校验**：接受候选时重新合成，保护区与有效合成区外逐字节不变，否则拒绝。
2. **确定性文字**：文案、价格、Logo 以对象合成；导出时 OCR 校验关键文本（用户标记为「关键」的
   文本对象）精确匹配；不匹配阻断导出并指出对象。
3. **规格检查**：画布尺寸、Provider 尺寸约束（16 倍数、像素上限）、导出预设规格。
4. **输出结构检查**：透明任务必须实际含 alpha；可解码但不符合规格的产物单独留存、回执标 partial。
5. **VLM 去偏**：自检按 brief 拆成原子问题；多选一时打乱顺序复评；结论只写入观察记录。
6. **漂移重置**：多轮编辑漂移时回到基础修订重新生成，不在模型输出上叠加。
7. **可回归评测**：固定 golden set 与 rubric，换模型或升级引擎时跑对比并记录；人工定期复核。

安全：工程读写只接受索引内项目与附件白名单来源；拒绝 URL、symlink、非普通文件；
Provider 请求只允许 HTTPS 或 loopback，拒绝带凭据的 URL；凭据只在 Agent Host 进程内存。

## 11. 模型与 Provider

- 图像模型是 Pi 配置（`models.json`）里的 `type: "image"` 模型；每次生成都经 Pi 的
  `modelRegistry.generateImages()`，由 Pi 解析凭据（key、环境变量、OAuth），引擎自己不调用任何模型接口
  （ADR 0010 第 9 条，2026-10-09 修订）。`image-pi-extension` 通过 Pi 的 `ProviderConfigInput.images`
  注册 `openai-images` 图像 API 实现；蒙版、尺寸、质量、背景放在 `ImagesOptions.metadata` 里传递。
  引擎接收注入的生成函数，保留任务认领、部分回执、离线恢复和保护区合成。
- 配置方式（2026-10-09 用真实 Pi 1.0 SDK 验证）：Pi 1.0 的 `models.json` 只能声明对话模型，图像模型
  只能由 Provider 注册提供；扩展层一旦带 `models` 会整体替换该 Provider 的模型列表，所以图像模型挂在独立的
  `newmoney-images` Provider 上，不碰用户已有的对话 Provider。用户在 `models.json` 写
  `"newmoney-images": { "baseUrl": "...", "apiKey": "..." }`（key 也可放 `auth.json` 或 `$ENV` 插值）；
  扩展只读取其中的 `baseUrl` 并注册图像模型，key 由 Pi 在每次请求时解析。未配置时编辑类工具照常可用，
  生成在发出任何请求之前就报「未配置」。
- Provider profile 声明能力：生成 / 编辑 / 蒙版 / 参考图上限 / 透明 / 尺寸约束 / 质量档 / 价格表。
  任务 Composer 的模型选择器只列出用户已配置且 profile 可用的 Provider；没有默认推荐。
- 合同校验为 Node 实现；与 creative-craft canonical Image Job v2 / Execution Receipt 的语义通过
  共享样例保持一致（video harness 的双实现先例）。接入其他图像模型（如 Seedream）是在 Pi 里再注册一个
  图像 API 实现，引擎不变。
- 缓存：以 brief、参数、参考哈希为键缓存生成结果，避免重复请求；离线跑批可选 Batch API（后续）。

## 12. 数据模型与存储

### 12.1 工程目录（`newmoney.image-project.v1`）

```text
<project>/
├─ project.json              身份、标题、归属、格式版本、创建信息
├─ revisions/000001.json …   不可替换修订（父摘要、变更、作者来源 人/Agent）
├─ assets/<sha>.<ext>        原始素材；assets/<sha>.png 归正后的渲染素材
├─ fonts/<sha>.otf           工程绑定字体（内置 CJK + 用户添加）
├─ masks/<sha>.png           保护 / 生成 / 羽化蒙版
├─ candidates/<id>/          不可变候选、回执、决定
├─ jobs/<job_id>/            Provider 任务：Job、编译包、请求摘要、输出、回执
├─ exports/<ts>-<name>/      导出件与回执
└─ previews/<sha>.png        渲染缓存（可丢弃）
```

- 从 creative-craft `local-image.v1` 工程可**只读导入**并升级为 v1 新修订；不原地改写来源目录。
- 限制沿用执行器上限（画布 ≤ 16,777,216 像素、边长 ≤ 8192、素材 ≤ 20 MB、≤ 64 素材、≤ 100 对象、
  ≤ 1000 修订、≤ 64 候选 ID）；达到上限时界面明示并引导复制项目。
- 无引用素材与候选的垃圾回收是显式动作（`清理未使用素材`），带预览与确认。

### 12.2 创作库与索引

- 创作库根目录在第一次打开 `图像` 时由用户确认一次（一次性的「选择创作库位置」步骤，确认后才创建），
  之后可在 `设置 › 图像` 更改（更改只迁移索引，不迁移文件）。预填建议：macOS 为 `~/Documents/New Money/图像`；
  Windows 优先预填第一个非系统盘的固定磁盘（如 `D:\New Money\图像`），没有非系统盘才退回 `Documents`。
  素材、工程、导出件都在创作库内，不放系统盘 `userData`。创建时由 App 注册为受信任 Workspace，并在设置页显示路径。
- Main 维护 `userData/image-library/index.json`（项目 ID、路径、归属、标题、最新修订摘要、缩略图哈希），
  启动时与磁盘对账，缺失项目标为 `missing` 而非删除记录。`userData` 内只有这份索引与缩略图缓存，
  体积小且可随时删除重建；用户素材从不进入 `userData`。
- 缩略图按修订渲染摘要寻址存于 `userData/image-library/thumbs/<sha>.png`，可随时删除重建。

### 12.3 隐私

工程、提示词、素材、候选从不进入日志、诊断包、遥测、Workbench 持久化或私有记忆。
`diagnostics.collect` 只报告引擎版本、任务计数与耗时分布。

## 13. 进程、包与协议

### 13.1 进程拓扑

```text
Electron Main
  |- BrowserWindow → sandboxed renderer（画布、面板、对话）
  |     `- app://pi67/image/<projectId>/<kind>/<sha>   只读预览与缩略图
  |- 创作库索引、目录监听、导出到文件系统的对话框
  `- utilityProcess: Agent Host
        |- PiSdkRuntime
        |     `- image-pi-extension（registerTool → image_*）
        `- image-engine
              |- 项目队列（每项目串行，跨项目并行 ≤ 2）
              `- worker_threads 池（渲染 / 合成；60s 超时；AbortSignal）
```

- 图像引擎不进入 Main 的事件循环；Main 不渲染。只有 profiling 证明 Agent Host 响应或内存预算
  不满足时，才把引擎移入专用 utility process，policy 与队列仍留在 Agent Host。
- 不新增 localhost server 或本地 WebSocket；图像字节不经 Agent port 传输。

## 14. 设计系统与可访问性

- 使用 `DESIGN.md` 的语义 token、14px 面板圆角、安静表面与单像素分隔；画布背景使用 canvas token
  的更深一级，不引入纯黑。
- 状态用图标 + 文本表达（候选状态、任务状态、锁定），不只靠颜色；动效只表达状态变化
  （候选到达、修订更新、任务进度）。
- 键盘：所有面板操作可达；图层列表 Tab / 方向键；画布方向键微调 1px、Shift 10px；
  ⌘Z / ⇧⌘Z 撤销重做；⌘E 导出；`标记` 模式 Esc 退出。
- 画布对象与标记在图层列表中有文本等价；修订更新与任务状态变化通过 live region 播报。
- 对比度与有效点击尺寸按 `DESIGN.md` Accessibility 节执行；中文为主语言，所有新文案进入 `localization`。

## 18. 风险与未验证假设

## 19. 已决开放问题（2026-10-08）

1. 创作库位置：首次打开 `图像` 时由用户确认一次，Windows 预填非系统盘，见 12.2。
2. 用户字体：P3 只支持显式添加字体文件，不枚举系统字体。
3. 工作区归属项目的目录固定为工作区内 `.newmoney/images/<id>/`。
